# Gate 1 report — deterministic relationship-regression vertical slice

## Claim tested

This gate proves one narrow mechanism only:

```text
controlled primary polygon mutation
  -> dependent WITHIN assignment delta
  -> deterministic evidence
  -> explicit BLOCK policy result
```

It is not a general GIS-safety, format-support, scalability, CI, or production
readiness claim.

## Fixture construction

The mathematical construction is in EPSG:25830. It is a synthetic Madrid-like
example, not official administrative data. The common vertical extent is
`y = 4470000..4470200`, so its height is 200 m.

| State | Chamberi x-range | Tetuan x-range |
|---|---:|---:|
| BASE | 440000..440100 | 440100..440200 |
| CANDIDATE | 440000..440060 | 440060..440200 |

Thus the shared boundary moves west by exactly `440100 - 440060 = 40 m`.
The controlled changed strip is `x = 440060..440100` by 200 m high, hence
its ideal area is `40 m × 200 m = 8,000 m²`. Each district's symmetric
difference is that same strip; unioning them counts it once.

The GeoJSON fixture files are RFC 7946 CRS84 coordinate payloads. Their
coordinates were generated by inverse transformation from the EPSG:25830
construction and the loader transforms them with PyProj back to EPSG:25830
using `always_xy=True` before every predicate and measurement. This preserves
the Gate 0 CRS contract; no GeoJSON input is treated as metric coordinates.

Fixed dependent coordinates are specified in the same construction:

- `hotel_813`: (440080, 4470050), Chamberi before and Tetuan after.
- `hotel_unchanged`: (440030, 4470050), Chamberi in both states.
- `poi_212`: (440070, 4470150), Chamberi before and Tetuan after.

## Measured primary change

The implementation uses topological equality to mark a primary feature
modified or unchanged, polygon symmetric difference for the footprint, and
Shapely's discrete Hausdorff distance for maximum controlled boundary
displacement. Both `chamberi` and `tetuan` are modified.

| Measurement | Ideal construction | Observed fixture run | Acceptance tolerance |
|---|---:|---:|---:|
| Changed footprint area | 8,000 m² | 8,000.0000001862645 m² | ±0.000001 m² |
| Maximum boundary displacement | 40 m | 40.0 m | ±0.000001 m |

The 1.862645×10⁻⁷ m² area difference is caused by decimal CRS84 fixture
serialization followed by projection, not a changed construction. The test
tolerance is therefore 1e-6 in fixture measurement units. This is recorded in
the decision log rather than presenting the rounded control target as exact
output.

## Relationship and boundary semantics

For every dependent feature, analysis calls the exact Shapely/GEOS
`dependent.within(primary)` predicate in EPSG:25830. It does not inspect
centroids, labels, nearest geometry, or bounding boxes to assign a district.

| Dependent | Before | After | Result |
|---|---|---|---|
| `hotels/hotel_813` | `[chamberi]` | `[tetuan]` | assignment_changed |
| `hotels/hotel_unchanged` | `[chamberi]` | `[chamberi]` | unchanged |
| `tourism_pois/poi_212` | `[chamberi]` | `[tetuan]` | assignment_changed |

The boundary test constructs a point by interpolating the actual shared
candidate boundary intersection after transformation. It has no WITHIN
assignment and reports both `chamberi` and `tetuan` in
`boundary_primary_ids`. A strictly interior point is within Tetuan; an outside
point has neither assignment nor boundary ambiguity.

## Evidence and policy

Each regression is content-addressed from canonical JSON containing its primary
dataset/IDs, dependent dataset/ID, predicate, before/after sets, and change
type. It has no timestamp, UUID, random input, or machine path. The evidence
also embeds the dependent Point geometry in the analysis CRS and labels it as
such; this gate does not emit an RFC 7946 evidence file.

| Dependent | Deterministic evidence ID |
|---|---|
| `hotels/hotel_813` | `relationship-regression-526712f2a3cfcdb0b86e03e9b060807c34ec8909095e5bb87cd57ab47e3cde49` |
| `tourism_pois/poi_212` | `relationship-regression-b9209f0fa3ca1ab124fd412de95dc593c002219a36c5053a94071855602a0c68` |

The only policy rule is `max_relationship_regressions`. With threshold 1 and
observed value 2, it returns `BLOCK` and includes both sorted evidence IDs.
The separate policy tests show `PASS` at equality and `BLOCK` above threshold.

## Tests executed

`py -m pytest` — **8 passed**.

The suite covers identical primary versions, the controlled reassignment,
strict-inside/boundary/outside cases, deterministic repeated analysis, policy
PASS/BLOCK, and footprint/displacement tolerance. It uses no clock, random
value, filesystem iteration order, or network.

Test environment: Python 3.14.5, Shapely 2.1.2, PyProj 3.7.2 / PROJ 9.5.1.

## Limitations

This is pure fixture code, not a CLI or general reader. It accepts only the
small GeoJSON FeatureCollections used by tests, assumes CRS84 input and
EPSG:25830 analysis, supports only Point dependents and Polygon primary
features for this proof, and implements only WITHIN plus one policy rule. It
does not produce a standalone report artifact, GeoJSON evidence layer,
configuration system, or CI integration.
